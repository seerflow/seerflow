# S-013: Regex-based entity extraction (IPs, usernames, hostnames, processes, files, domains)

**Linear:** [SEE-17](https://linear.app/seerflow/issue/SEE-17) | **Epic:** EPIC-002: Log Parsing | **Priority:** Must Have
**Points:** 5 | **Sprint:** 2 — First Log Parsed | **Dependencies:** S-012

## User Story

As the parsing layer, I want automatic entity extraction so that entities are identified for cross-source correlation.

## Acceptance Criteria

- [ ] Extracts IPv4 and IPv6 addresses from message body and attributes
- [ ] Extracts usernames from common log formats (auth, sshd, sudo, nginx)
- [ ] Extracts hostnames from OTel resource attributes and syslog headers
- [ ] Configurable custom extraction patterns via YAML
- [ ] Extracted entities populated in SeerflowEvent entity reference fields

## Deferred from S-002 and S-101 Code Reviews

> **Security (from S-002 review — Security Reviewer, MEDIUM):**
> - Validate `related_ips` with `ipaddress.ip_address()` — reject malformed IPs at extraction time
> - Enforce per-event cardinality caps on all entity tuples (e.g., max 256 IPs, 64 users, 64 hosts)
> - Validate username/hostname character sets via allowlist regex
>
> **From S-101 review — Security Reviewer, MEDIUM:**
> - Validate `related_hashes` format: `"<algo>:<lowercase-hex-digest>"` (e.g., `"sha256:e3b0c44..."`)
> - Max 50 hashes per event, max 80 chars per hash string
> - Character set restricted to `[0-9a-fA-F:]`
