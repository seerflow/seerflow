# S-046: Alert deduplication engine (hash-based dedup key, configurable window)

**Linear:** [SEE-70](https://linear.app/seerflow/issue/SEE-70) | **Epic:** EPIC-008: Alert Routing | **Priority:** Must Have
**Points:** 3 | **Sprint:** 8 — Graph Correlation + Alerts | **Dependencies:** S-042

## User Story

As an on-call engineer, I don't want alert storms from the same pattern.

## Acceptance Criteria

- [ ] Dedup key: hash of (alert_type, rule_name/model_type, entity_uuid)
- [ ] Within configurable dedup window (default 15 minutes): increment count, update timestamp
- [ ] After dedup window expires: new alert created
- [ ] Dedup count visible in dashboard and webhook payloads
- [ ] Configurable per-rule dedup window override
