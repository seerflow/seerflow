## Technical Notes

### Alert (from architecture doc line 660)

```python
class Alert(msgspec.Struct, frozen=True):
    alert_id: str
    alert_type: str             # "ml" | "sigma" | "correlation" | "ueba" | "ioc"
    timestamp_ns: int
    severity_id: int            # → SeverityLevel (typed like SeerflowEvent)
    rule_name: str
    description: str
    entity_uuid: str
    entity_value: str
    entity_type: str
    contributing_events: tuple[uuid.UUID, ...]
    mitre_tactics: tuple[str, ...] = ()
    mitre_techniques: tuple[str, ...] = ()
    risk_score: float = 0.0
    dedup_key: str = ""
    dedup_count: int = 1
    feedback: str = ""          # "" | "tp" | "fp"
```

### CorrelationRule (from architecture doc line 679)

### SourceCondition (from architecture Appendix D design)

A condition that matches events from a specific source within a correlation window:
```python
class SourceCondition(msgspec.Struct, frozen=True):
    source_type: str            # e.g., "syslog", "otlp", "file"
    conditions: dict[str, str]  # field_name → regex pattern
    min_count: int = 1          # minimum matching events required
```

### Query Types (from REST API section, line 781)

Derived from the REST API query parameters:
- `GET /events` → `EventQuery(since, until, source_type, severity_id, template_id, entity_uuid, q, page, limit)`
- `GET /alerts` → `AlertQuery(since, until, alert_type, severity_id, entity_uuid, page, limit)`
- `TimeRange(start_ns, end_ns)` — reusable time range
- `Page[T](items, total, page, limit)` — generic paginated response

### Design Decisions

- **Alert uses `frozen=True` but NOT `gc=False`** — alerts are not on the hot path (orders of magnitude fewer than events). Keeping GC tracking is safer for the `contributing_events` tuple of UUIDs.
- **Query types as `dataclasses`** — not msgspec Structs. Queries are ephemeral request objects, not serialized to storage. Dataclasses are simpler and support `Optional` fields cleanly.
- **`Page[T]` is generic** — enables `Page[SeerflowEvent]`, `Page[Alert]`, etc.
- **`AlertType` and `Feedback` as `Literal` types** — catches typos at type-check time without enum overhead.

## Architecture Context

- **Alert** is produced by 5 different sources: ML ensemble, Sigma engine, correlation engine, UEBA scorer, threat intel matcher. All must produce the same Alert struct.
- **CorrelationRule** is loaded from YAML files and hot-reloaded. Used by the correlation engine (S-041).
- **EventQuery/AlertQuery** are consumed by the Storage Protocols (LogStore, AlertStore) — they're the typed filter objects passed to `query_events()` and `query_alerts()`.
- **Page[T]** is returned by all paginated storage queries and forwarded directly to REST API responses.

## Brainstorm Notes

1. **`AlertType` as `Literal`** — `Literal["ml", "sigma", "correlation", "ueba", "ioc"]`, msgspec validates natively
2. **`Feedback` as `Literal`** — `Literal["", "tp", "fp"]`, empty string = no feedback
3. **`SourceCondition.conditions`** — `dict[str, str]` (field_name → regex pattern)
4. **`Page[T]`** — fields: `items`, `total`, `page`, `limit`; `has_next` as `@property`
5. **All query filter fields `Optional`** — `X | None = None` for composable filtering
6. **Query types as `@dataclass(frozen=True, kw_only=True, slots=True)`** — not msgspec Structs (never serialized)
7. **`Alert.severity_id: SeverityLevel`** — matching S-002 decision
8. **Background doc `TimeRange`** — adopt `@dataclass(frozen=True, slots=True)` with `start_ns`, `end_ns`
9. **Background doc `EventFilter`** — adopt field structure, rename to `EventQuery`, use `page`/`limit` (REST API consumer)
