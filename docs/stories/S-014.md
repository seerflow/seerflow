# S-014: Field normalization (source-specific → SeerflowEvent mapping)

**Linear:** [SEE-18](https://linear.app/seerflow/issue/SEE-18) | **Epic:** EPIC-002: Log Parsing | **Priority:** Must Have
**Points:** 3 | **Sprint:** 2 — First Log Parsed | **Dependencies:** S-012, S-013

## User Story

As the pipeline, I want all events normalized to the SeerflowEvent schema regardless of source.

## Acceptance Criteria

- [ ] All events from all sources produce valid SeerflowEvent structs
- [ ] OTel SeverityNumber (1-24) mapped to severity_id (0-6)
- [ ] Syslog severity (0-7) mapped to severity_id (0-6)
- [ ] timestamp_ns and observed_ns populated for all events (nanosecond precision)
- [ ] raw_event field preserves original event text
- [ ] source_type and source_id populated for provenance

## Deferred from S-002 and S-101 Code Reviews

> **Security (from S-002 review — Security Reviewer, HIGH/MEDIUM):**
> - Enforce max field lengths at ingestion before constructing SeerflowEvent:
>   - `MAX_MESSAGE_LEN = 8_192` (8 KB)
>   - `MAX_RAW_EVENT_LEN = 65_536` (64 KB)
>   - `MAX_ATTRIBUTE_KEY_LEN = 256`
>   - `MAX_TEMPLATE_PARAMS = 64`
> - Validate `trace_id` format: 32-char lowercase hex (`^[0-9a-f]{32}$`)
> - Validate `span_id` format: 16-char lowercase hex (`^[0-9a-f]{16}$`)
> - Reject CRLF/control chars in `trace_id`, `span_id` to prevent header injection
> - Document LLM prompt injection risk: all `message`, `raw_event`, and `body` content must be treated as untrusted input and sandboxed before inclusion in LLM prompts
>
> **From S-101 review — Security Reviewer, LOW:**
> - Validate `activity_id` range (0-99) per OCSF spec — enforce invariant `type_uid = class_uid * 100 + activity_id`
> - Validate `category_uid`, `class_uid`, `type_uid` consistency when all three are set
