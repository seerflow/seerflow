# Show HN: Seerflow — streaming log anomaly detection you can run in 60 seconds

Seerflow is an open-source (AGPL-3.0) streaming log-intelligence agent. It
ingests logs from syslog / OTLP / files / webhooks, extracts templates with
Drain3, resolves entities to deterministic UUIDs, scores every event with an
online ML ensemble (Half-Space Trees + Holt-Winters + CUSUM + Markov),
auto-thresholds with biDSPOT (no manual tuning), evaluates 63 bundled Sigma
rules with MITRE ATT&CK tagging, and accumulates per-entity risk — all in a
single zero-config `pip install`, SQLite by default.

## Why we built it

SIEMs are heavy. Most teams want "tell me when something is weird" without
standing up an Elastic cluster. Seerflow is a lightweight streaming detection
layer: constant-memory online detectors, one process, runs on a laptop.

## Try it (under a minute, no Docker, no config)

```bash
pip install seerflow

# Deterministic end-to-end demo (boot -> ingest -> detect -> alerts)
python -m seerflow.launch.demo

# Real benchmark on your hardware (throughput / latency / memory)
python -m seerflow.launch.benchmark --count 20000 --markdown

# Detection-quality validation (precision / recall / F1 / FP-rate)
python -m seerflow.lanl.report
```

Everything above is committed and runnable. We do not ship invented numbers —
the benchmark prints what *your* machine measures, and detection quality is
validated against a synthetic LANL subset (see the **Validation** section of
the README, regenerated by `python -m seerflow.lanl.report`).

## Record the demo

```bash
python -m seerflow.launch.record demo.cast --exec   # requires asciinema
# or, offline: print the command and run it yourself
python -m seerflow.launch.record demo.cast
```

The recording wraps the deterministic `python -m seerflow.launch.demo`, so
the asciicast is reproducible.

## How it compares

Seerflow is not a SIEM replacement — it is a streaming anomaly + rule
detection layer you run in minutes. See the **How Seerflow Compares** table
in the README for the category-level comparison against Wazuh, OpenSearch,
and Splunk (deployment posture and approach, deliberately not version-pinned).

## Honest limitations

- Benchmark numbers are hardware-dependent — reproduce, do not trust ours
  blindly.
- Detection quality is validated on a *synthetic* LANL subset (~200 events),
  clearly labelled as such; the harness is dataset-agnostic so you can point
  it at the full downloaded LANL dataset.
- Single-node SQLite by default; PostgreSQL backend for scale.
