## Why

S-180 (SEE-195) landed the docs drift guard inside `seerflow-guide`, which means a code PR on `seerflow` that renames a config key only triggers the drift check when somebody opens a PR on `seerflow-guide` afterwards. The earlier reactive fixes (S-139G-F1, S-139G-F2) were both renames-on-seerflow that the docs side noticed late.

Better DX: also run the drift script on every seerflow PR, against the published seerflow-guide. CI on the code PR fails immediately, so the dev fixes both repos in one cycle.

## Scope

1. Lift `scripts/check_docs_drift.py` from seerflow-guide and place a sister copy in `seerflow/scripts/check_docs_drift.py` (or import via a slim shim). Tracking divergence is the main risk — prefer fetching the canonical script at workflow time over duplicating.
2. Add a new workflow `.github/workflows/docs-drift.yml` to seerflow that:
   - Triggers on pull_request when `src/seerflow/config.py` or `src/seerflow/cli.py` changes.
   - Clones seerflow-guide@main, installs the docs project, runs the drift script with `--docs-dir docs`.
   - Fails the PR if drift is detected; posts a comment with the offending keys/flags.
3. Update CLAUDE.md and `.bmad/templates/story-template.md` (if tracked) so docs-impacting stories know about the gate.

## Acceptance Criteria

- [ ] `scripts/check_docs_drift.py` (or equivalent fetch step) is invocable from seerflow's CI.
- [ ] `.github/workflows/docs-drift.yml` triggers on the right paths.
- [ ] A test PR that renames a config key fails the workflow with a clear message.
- [ ] CLAUDE.md mentions the new gate.

## Definition of Done

- [ ] All acceptance criteria checked.
- [ ] Companion explanatory note added to the seerflow-guide drift workflow describing the seerflow-side counterpart.
